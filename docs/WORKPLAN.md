# Workplan — Aperture to a deployed, universal instrument

*2026-09-02. Ponytail throughout: the shortest working diff, delete before adding, no
abstraction with one caller. Subagents are Opus only. Codex (gpt-5.6-sol, luna as fallback) is
local-only: it indexes, condenses and reviews; it never ships and never touches a deployment.*

## What "done" means

A researcher opens a URL, signs in with an account an admin made for them, starts a project,
drops in files of several kinds, and reads the analysis: material pages with claims beside the
text they rest on, theme pages across the corpus, a corpus summary, an export. Every quote is
verified. Every number is a derivation. No JavaScript. It looks like an instrument someone was
proud to make.

## Phases, owners, order

```
P1 index+condense (codex) ─┐
P2 repo hygiene (me)       ├─ parallel ─→ P5 design (me) ─→ P7 reviews (codex) ─→ P8 deploy (me)
P3 accounts (Opus A)       │                  ▲
P4 material intake (Opus B)┤                  │
P6 export (Opus C)         ┘──── land first ──┘
```

| # | What | Who | Gate |

| P3 | **Accounts.** `user(id, name, password_hash, is_admin)`; `scrypt` from the stdlib; one session cookie; a sign-in page; an admin page that creates users and lists everyone's projects; a project belongs to a user; the PIN gate is deleted. No email, no reset, no OAuth. | Opus A | tests: a user sees only their projects; an admin sees all; nobody sees anything signed out |
| P4 | **Material intake.** Upload one or many files: `.txt` `.md` `.docx` `.pdf` `.csv`, plus paste. `python-docx` and `pypdf` for the two binary kinds; a CSV of open answers becomes one material of respondent-headed passages. One file → one material → the chain. Nothing here decides what a material *is* — FRAME does. | Opus B | tests per kind: text arrives as sentences with ids; a CSV keeps its respondents apart; a bad file fails with a sentence, not a trace |
| P5 | **Design.** A token system (colour, type, spacing), the two registers kept sacred — the material never looks like the app and the app never looks like the material — the derivation numbers, light and dark, every page. Still no JS. | me | every page at 360px and 1400px, both themes, by eye |
| P6 | **Export.** One markdown document with a contents list: corpus summary → theme accounts → each material (orientation, reading, lines) → checks → what was set aside → the researcher's comments → runs and cost. | P7 | **Reviews.** Codex reads each phase's diff for over-engineering and against law 5; reads every page's copy for banned vocabulary and for plain sense. Findings back to me; I fix. | codex | no finding above "nit" open |
| P8 | **Deploy.** New public GitHub repo `RJuro/aperture`; new Coolify app mirroring the existing one's server and destination, at `aperture.automate.business.aau.dk`, storage at `/data`, provider `mistral`; first admin created from an env var on first boot; live walkthrough: sign in, make a user, make a project, upload the two seeds, read. **Never rename the app after creation.** | me (the user removes the old repo and app when ready) | the walkthrough passes on the deployed URL |

## Rules that hold across every phase

- Law 5. A prompt template is universal; a slot holds material, structure, or the researcher's
  words. `tests/test_p9_law5.py` runs on every change.
- Our vocabulary stays out of every page: `context._BANNED`.
- Every phase ends with a real-output check, not a green suite.
- Every subagent owns named files and touches nothing else; the contract tests are written by
  me before it starts.
- Codex is local-only. Nothing it produces is deployed without my reading it.
