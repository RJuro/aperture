Add materials

Open a project and select Add material. Choose one or more files, or paste text and give it a name. Select Add material to start the analysis.

Each file becomes one material. Aperture identifies its structure, assigns codes, and produces themes and summaries with links to the source text. Processing continues if you leave the page; check the progress message to see which step is running. Stop halts it between steps.

Supported files: TXT, Markdown, Word (.docx), PDF, and CSV.

How analysis works · Choosing an analysis method

How analysis works

Each material is taken through the same order: working out how it is laid out, working out what to look for in it, and coding it. From there the two methods part — see Choosing an analysis method for what changes between them. Last comes the corpus level in both: a summary of each theme across everything, then the project summary.

It costs model calls and takes minutes rather than seconds. Input and output tokens per step are printed in the analysis record.

Analyse each material independently, or using existing project codes?

Analyse each material independently shows the reading no project codes at all — only the material, how it is laid out, what to look for in it, and your focus in your own words. It names codes for what this material says. Afterwards a separate step compares those codes with the project's vocabulary, saying of each that it is the same as an existing code, narrower, wider, or distinct; only then do themes move. This resembles inductive first coding in reflexive thematic analysis.

Analyse using existing project codes shows each reading the project's live codebook and theme set, so later material is read against a developing framework — the framework itself can still change as more material arrives; it is not fixed at the first file. This resembles template analysis and framework analysis.

Neither is the correct one. Analysing each material independently costs a further call per material, coins many more codes, and converges more slowly — in the one measured run two materials read this way produced eight candidates and nothing across them. Analysing using existing project codes settles the vocabulary from the first file, which is cumulative comparison and is also lock-in.

Changing this applies to material read from then on. Nothing already read changes.

What does the research focus do?

It goes to the model exactly as you typed it. Nothing paraphrases it, summarises it or turns it into an instruction of its own: the reading, the theme grouping, every line of claims and every summary are shown your words, unaltered. That is deliberate. Prose the instrument wrote about your corpus is never allowed back into a prompt as if it were your intent.

Editing it runs nothing. Material already read stays exactly as it was read, under the focus it was read under; the new wording reaches the next reading and every write-up after it. If you want material already read to be read under the new focus, that is a deliberate act with a price: run that material again from Coding.

Angles are the one thing the focus is kept away from. They are worked out before a reading, to say where to look, and are shown the questions earlier material raised rather than your focus — so they can disagree with it.

What is a theme here, and what does locking a definition do?

A theme is a definition — one that would still be true if fifty more materials arrived — and never a finding. What a theme amounts to across the corpus is a separate object, its theme summary, written over the claims. The instrument will not let one become the other.

A theme is held in one of three ways. Candidate: found in one material so far, not yet added to the project's themes. It is not counted against the ceiling and gets no theme summary. Open: a project theme still developing — its definition can change, and the grouping step may reword, regroup or merge it. Locked: you have declared the definition final.

Found in 2 cases — becomes a project theme? is a count. A comparison automatically adds a candidate to the project's themes once it has claims in at least half of the project's counting units, rounded up, with a minimum of two. Below that threshold, a comparison leaves it a candidate; outside a comparison, you add it to the project's themes by hand, using Add to project themes on its own page. Prevalence is not importance.

Locking a definition fixes the name and definition in code. New material is still analysed against a locked definition; what pulls against it comes back as a note on its page rather than being written into the definition. Unlocking is one click, and those notes are the case for it.

Unchanged for 3 passes counts grouping passes in which nothing about the theme moved. It is bookkeeping, not saturation.

How do I read in 2 of 3 cases (4 materials) · 21 claims on 20 passages?

Every number on every page is printed as the derivation it came from, over rows the page links to. None of them is stored; open the rows and you can check the arithmetic.

2 of 3 cases (4 materials) — how far the theme reaches. Where you have grouped files into cases it counts cases, with the material count in brackets, because the columns beside it are materials and a reader has to be able to check one against the other. Where you have grouped nothing it says materials, and that is a fact about your upload rather than about your corpus.

21 claims on 20 passages — two numbers because they are two different things. Two claims resting on one passage are one piece of evidence read twice. A theme with many claims on few passages is thinner than its claim count suggests.

3 passages shared with other themes — evidence two themes are dividing between them. Passages are not owned by one theme.

A dash in a cell is not a zero. It carries which kind of assessment status it is; see Empty cells.

What is a line of claims under a theme?

One theme followed through one material: short claims in the order the material makes them, each resting on a verbatim quote of at most twelve words. The quote is authoritative, not the citation — Python looks for it in the text, repairs a wrong passage id, and drops a claim whose quote is not there. A claim you can read without its quote being findable does not reach the page.

After the claims are written they are checked once against the passages they rest on. A claim the passage carries only in part is kept and says so wherever it is read; a claim the passage does not carry is set aside with its reason, and the material's Excluded list shows it.

sparse · 2 claims means the line is shorter than a full one. It is kept and said to be short, because three observations and thirty should not read alike on a page. It is a finding about this material, not a failure of the reading.

Also read under means the same passage carries a claim under another theme. That is ordinary, and worth reading: it is where two themes overlap.

What does an empty cell mean?

Numbers count claims. Cells without a count show the assessment status, one of five, recorded separately, because reading them alike is how a corpus comes to say that eleven themes run through all four interviews.

  • No retained claims. The theme was assessed in this material, but no claims were retained. Check the Excluded list before reading this as absence: a set of claims too thin to keep is dropped whole.
  • Source check skipped. A preliminary review of the summary and codes did not select this theme for a source check in this material. Its reason is shown with the status.
  • No matching codes. None of the codes this theme gathers marked this material, so the initial coding did not trigger an assessment. This is a fact about where the coding went, not about what the material says.
  • No match in uncoded passages. Only in a project that analyses each material independently: none of the theme's codes marked this material, so no line was written, and a last pass then read every passage no code had touched with this theme in view and found nothing to add. This is the nearest thing to a searched absence the instrument produces on its own, and it is still a statement about what was searched, over the passages the coding did not mark.
  • Not assessed. This material has not been assessed for this theme — it arrived after the theme was worked out, or the theme after the material was read.

The instrument never writes absent as a conclusion of its own. A negative statement is something you run: Check against the material, over the passages no claim rests on yet, answers nothing found — searched 41 passages not yet cited. That is a statement about what was searched, and it is as far as the evidence goes.

Where does a comment go, and what does it rewrite?

Where you leave it decides what runs. Your words reach the model verbatim in every case.

  • On a line of claims — that line again, for that material and that theme only; then the material summary over the claims that now stand; then every theme summary; then the project summary.
  • On a material summary — the summary again over the claims that stand, then the theme summaries and the project summary. It does not rewrite any line.
  • On a theme summary — that theme summary across the corpus, then the project summary above it.
  • On the project summary — the project summary, and nothing else. It does not re-read a single material. A comment that is really about one theme belongs on that theme.
  • On one claim — nothing runs now. It is stored, shown and exported, and the next rewrite of that material is shown it.

Nothing you write ever causes a material to be read again. Re-reading under the influence of an opinion is exactly what the quote rule exists to prevent; if you want a re-reading, ask for one (below). A comment is marked honoured by a rewrite only by a run that was actually shown it; until then the record says open.

What does “run again from …” redo?

This is the one verb that may read a material a second time, because you asked for it. Each starting point runs everything after it, in the order a fresh upload uses, and then the corpus level.

  • Structure — how the material is laid out, then what to look for, then read it, group themes, write it up.
  • Angles — what to look for, then read it and everything after.
  • Coding — read it again, then themes and the write-ups.
  • Themes — group the codes again, then the write-ups.
  • Synthesis — write this material up again, then the project summary.

A second reading replaces the first: this material's code marks go before it runs, and a code left with nothing loses its place in every theme, exactly as when the material is removed. Passage ids never change, so correcting the layout leaves codes and claims where they were.

The optional note is stored once as a comment on the material and shown to every step in the chain, so the summary at the end is still holding it. Cost is roughly what a fresh upload costs from that step on.

What does “check against the material” do?

It searches and records. It changes no reading, rewrites no summary, and adds no claim to any theme — which is why it is the safe way to test your own doubt about a claim.

Two scopes. Search everything reads every passage in scope. Only passages no claim rests on yet reads the remainder — the part of the material the reading passed over — which is the question did the reading miss this? rather than is this in here?

The verdict is Python's, not the model's: quotes that can be found in the text mean found, and none means nothing found — searched 41 passages not yet cited. That is not the material contains none of this; searching the uncited remainder and finding nothing says nothing about the passages a claim already rests on. The model's opinion can only lower confidence, never raise it.

Every check keeps its question, its verdict, its quotes and the number of passages searched, on the page and in the record.

Why group files into a case?

A file is not a case. Two files from one participant are two materials and one case. A spreadsheet of forty open responses is one material and, unless you say otherwise, one case. Neither count grounds a statement about recurrence across independent cases — which is what in 3 of 4 materials gets read as.

Until you say which files are one participant, one interview or one time point, every reach on every page is counted over files, and that is a fact about your upload. Make one case and the counting changes everywhere at once: reach is counted over cases, with the material count kept beside it, and the group of themes nothing has yet repeated is headed In one case so far. A material in no case counts as its own.

Grouping costs nothing and runs nothing. It changes what the numbers are counted over, not what was read.

What is in the analysis record, and what should I cite?

Everything the reading arrived at, on one page and in two downloads — Word and Markdown, the same content.

Each theme has a section that cuts across the corpus: its definition, its theme summary, the materials that carry it and the materials that do not, with which kind of assessment status each one carries. Each material has a section with its description, its material summary, and its claims printed once with their quotes and passage ids. A claim appears under its material and is cross-referenced from the theme, so nothing is counted twice by being printed twice.

Then: every question you checked with its verdict and the number of passages searched; what the reading excluded and why; every comment you left, with the thing it was about named and whether a rewrite has honoured it; how each theme's wording changed over time; and the processing history — runs, input and output tokens, provider and model per step.

Cite a claim by its material and passage id. The quote is what it rests on, and the record carries both.

Who else can open a project?

Only the owner shares. Sharing makes a standing link, carrying either collaborate or read only, that anyone signed in can take up until you revoke it. Revoking a link stops new people joining; people who already joined stay members until you remove them, which is a separate control on the same page.

A member who may only read opens every page and both downloads, and can run nothing. Comments, checks, adding material, adding a theme to the project, locking a definition, running again, editing the focus and grouping cases all answer them as if the project were not there. It is the same answer a stranger gets, on purpose: telling someone a project exists but is shut to them is still telling them it exists.

An administrator of the instance sees project names and owners and nothing of what is in them. Administering the instance is not a way into anyone's material.

Where does this sit in qualitative method?

The instrument does not do reflexive thematic analysis, template analysis or any other method. You do. What it does is read, code, group and write up, and then show you the evidence under every number so you can disagree with it. What it takes from each tradition:

  • Reflexive thematic analysis (Braun & Clarke 2006; their 2019 answers to frequently asked questions; 2021 on saturation) — a theme is an analytic output the researcher develops, not a category certified by appearing twice; prevalence is not importance; an unchanged definition is operational stability and not exhausted interpretation. Hence automatic promotion inside a comparison and researcher-initiated promotion outside one, the count printed as a question, and unchanged for N passes printed as bookkeeping.
  • Template analysis (King 2012; Brooks and colleagues 2015) — a working template that the analyst declares final, after which material is applied to it. Hence locking a definition, and tension notes kept outside it.
  • Framework analysis (Ritchie & Spencer 1994; Gale and colleagues 2013) — the case-by-theme matrix, with cells that say what is actually known rather than a bare count. Hence the five assessment statuses.
  • Constant comparison and negative cases (Glaser & Strauss 1967; Charmaz 2006) — comparing each new case with the developing account, and looking for what does not fit. Hence the code comparison step, and searching the uncited remainder.

What it does not claim: that its themes are yours, that its counts are evidence of importance, or that anything it could not find is not there.
